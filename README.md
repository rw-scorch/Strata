# Strata

A multiplayer voxel sandbox for the browser, built touch-first for iPad and phones and also playable on desktop. You dig, build, craft and survive in an endless procedural world. You can play alone, or invite friends to a world hosted on Cloudflare with an 8-character room code.

- **Wayfarer (Survival):** health, hunger, armour, experience, day/night creatures, crafting and smelting.
- **Architect (Creative):** unlimited blocks, flight, instant breaking, item search, time/weather control and the **World Shaper** (fill, hollow, outline, clear).

All built-in textures, creatures, icons, sounds and music are generated by the game itself. No Mojang assets are bundled (see [Vanilla textures](#vanilla-minecraft-textures)).

---

## Quick start

Requires Node.js 20 or later.

```bash
npm install
npm run preview        # typecheck, production build, then serve everything on http://localhost:8787
```

`npm run preview` runs the real Worker and Durable Object locally through `wrangler dev`, so multiplayer works locally too. Open two browser windows to try it.

For hot reload while developing the client:

```bash
npm run dev:worker     # terminal 1: Worker + Durable Objects on :8787 (serves the last build of dist/)
npm run dev            # terminal 2: Vite on :5173, proxies /api and /ws to :8787
```

To test on an iPad or phone on the same Wi-Fi, use the network URL that Vite prints.

Other scripts:

| Script | What it does |
| --- | --- |
| `npm test` | Unit tests: world generation, meshing, inventory/crafting, simulation, pack import |
| `npm run typecheck` | Type-checks the client, the Worker and the build config |
| `npm run build` | Typecheck and production build into `dist/` |
| `npm run deploy` | Build, then `wrangler deploy` |

## Deploying to Cloudflare

Strata deploys as **one Cloudflare Worker**. It serves the static game from `dist/` (Workers Static Assets with SPA fallback) and routes `/api/*` and `/ws/*` to the Worker. Each multiplayer world is its own **Durable Object** (`WorldRoom`) with SQLite storage. Two small global Durable Objects sit beside them: `Accounts` (optional logins) and `Registry` (the list of worlds and online players that the admin console reads).

Nothing else is required: no D1 database, no R2 bucket and no KV. Optional secrets: `ADMIN_KEY` lets you claim admin in any world with `/admin <phrase>` and opens the server admin console; `TURN_KEY_ID` and `TURN_KEY_API_TOKEN` add a TURN relay for voice chat. Durable Objects with SQLite storage are available on the Workers Free plan.

### Option A: from your computer

```bash
npx wrangler login
npm run deploy
```

Wrangler prints the live URL (`https://strata.<your-subdomain>.workers.dev`). The first deploy applies the Durable Object migration (`v1`, `new_sqlite_classes: ["WorldRoom"]`) automatically.

### Option B: from GitHub with Workers Builds (no tokens)

1. Push this project to a GitHub repository.
2. In the Cloudflare dashboard, go to **Workers & Pages → Create → Import a repository** and pick the repo.
3. Build command: `npm run build`. Deploy command: `npx wrangler deploy`. Leave the root directory as `/`.
4. Save. Every push to your production branch builds and deploys.

### Updating an existing deploy without losing anything

Worlds and accounts live in Durable Object storage on Cloudflare, not in the repo, so updating code never touches them. Durable Object migrations in `wrangler.jsonc` only ever add classes.

1. Make a backup branch: `git checkout main && git pull && git checkout -b backup-$(date +%Y%m%d) && git push -u origin HEAD && git checkout main`
2. Check `"name"` in `wrangler.jsonc` matches your Worker's name in the dashboard.
3. Put the new `strata-vN.zip` in the repo root, then run:
   `Z=$(ls strata-v*.zip | sort -V | tail -1) && rm -rf /tmp/strata_new && unzip -q "$Z" -d /tmp/strata_new && cp -r /tmp/strata_new/strata/. . && rm -rf /tmp/strata_new "$Z" && npm install && npm run build && git add -A && git commit -m "Update Strata ($Z)" && git push`
4. Workers Builds deploys the push. Roll back from the Deployments tab if needed.

Set `ADMIN_KEY` once under Settings, Variables and Secrets (type Secret). It persists across deploys.

Old clients keep working: the server accepts protocol versions from `MIN_PROTOCOL_VERSION` up to `PROTOCOL_VERSION`, new message fields are optional, and an outdated tab reloads itself once.

If you use Workers Builds, do not also add the GitHub Actions deploy secrets below, or every push deploys twice.

### Option C: GitHub Actions

`.github/workflows/deploy.yml` runs tests and the build on every push and pull request. It deploys on pushes to `main` when these repository secrets exist:

- `CLOUDFLARE_API_TOKEN`: an API token with the **Edit Cloudflare Workers** template permissions.
- `CLOUDFLARE_ACCOUNT_ID`: your account ID (shown on the Workers overview page).

### Configuration reference (`wrangler.jsonc`)

| Key | Purpose |
| --- | --- |
| `main: workers/index.ts` | Worker entry: API routes, WebSocket routing, static assets |
| `assets.directory: ./dist` | Built game files |
| `assets.not_found_handling: single-page-application` | `/join/ABCD2345` invitation links load the app |
| `assets.run_worker_first: ["/api/*", "/ws/*"]` | Only API and WebSocket paths hit the Worker; everything else is served from the edge cache |
| `durable_objects.bindings: WORLD_ROOMS → WorldRoom` | One object per room code |
| `migrations: v1 new_sqlite_classes` | Creates the SQLite-backed Durable Object class |
| `migrations: v3 Registry` | Added in v10 for the admin console. Cloudflare applies it automatically on the next deploy; existing worlds are untouched |

Custom domain: add one under the Worker's **Settings → Domains & Routes**. Invitation links use whatever origin players open the game from, so nothing needs to change in code.

Split hosting (optional): to host the static site elsewhere and point it at a separate Worker, build with `VITE_SERVER_URL=https://your-worker.example.workers.dev npm run build`.

### Why no D1 or R2?

Room metadata, player saves, chests, furnaces and modified chunks all live in each room's own Durable Object SQLite database. That keeps every world isolated and strongly consistent, and nothing large is held in Durable Object memory or D1 rows:

- Chunks are stored **only once modified**, as run-length-encoded rows, typically 2-8 KB each. Unmodified terrain is regenerated deterministically from the seed on both client and server.
- The server keeps at most about 450 chunks in memory and evicts the least recently used ones.
- Hosted-world lists are kept per device. The owner can delete a world from the Multiplayer screen.

If you later want cross-room features such as a public server browser or offsite backups, D1 (room index) and R2 (exports) are the natural additions. They are not needed for anything the game does today.

## Multiplayer

- **Create world:** name, seed, mode, difficulty, maximum players (default 20, up to 50; worlds that still had the old default of 8 were raised to 20), server region hint, PvP, guest building, commands, and resource pack sharing. You get a room code plus copy, share and invitation-link buttons.
- **Join:** enter a code or open `https://<site>/join/CODE`. A preview shows the owner, current players, free slots, version compatibility and the shared pack. Errors cover invalid codes, deleted worlds, full rooms, version mismatches, and connection or authentication failures.
- **Persistence:** a world keeps running in its Durable Object and is saved to SQLite every 10 seconds and when the last player leaves. It does not disappear when the host closes the browser.
- **Room management:** owner badge, player list, kick (with a 10-minute ban), mute, and world settings (name, difficulty, max players, PvP, guest building, commands, shared pack). Connection status and automatic reconnection are built in.
- **Proximity voice chat (v10):** like Simple Voice Chat. Turn it on in Options > Voice Chat. Players within 48 blocks hear each other, quieter with distance and positioned left or right. Push-to-talk on V (or the Talk button on touch screens), or voice activation with an adjustable level. M mutes your microphone. Audio goes directly between players over WebRTC; the server only passes the connection setup between players who are near each other. Owners can turn voice off per world. Hiding a player's chat also mutes their voice for you.
  - Optional TURN relay: some home or school networks block direct connections. Add two secrets to the Worker, `TURN_KEY_ID` and `TURN_KEY_API_TOKEN`, from Cloudflare dashboard > Realtime > TURN Server, and Strata will hand out short-lived TURN credentials from `/api/turn`. Without them, STUN only is used, which works for most players.
- **Waypoints (v11), in the spirit of wWaypoints:** press B to drop a waypoint where you stand and N to open the map and waypoint list (or tap the minimap). Waypoints have a name, editable X/Y/Z, colour, a 1-2 letter icon, a group (folder), an optional coloured beam with a block outline, and "remove on arrival". The list can be searched, groups fold and can be hidden together, and Shift+N hides all of them in the world. Dying drops a red death waypoint (the last 3 are kept, and each removes itself when you reach it). Coordinates typed in chat ("meet at 120 64 -300") get a Save button. Import accepts Strata JSON, wWaypoints clipboard JSON (best effort; its exact format is not published), Xaero's Minimap lines, VoxelMap lines, JourneyMap JSON and plain "Name: x y z" lines, from a file or pasted text. Export gives Strata JSON, the Xaero format, or text to copy. When a world hides coordinates, the waypoint screens show distances only.
- **Skins (v11):** Options > Skin Customization. Import any Java Edition skin PNG: 64×64, old 64×32 files (converted to the modern layout with mirrored limbs) and HD skins (scaled to 64×64). Slim (Alex) or wide (Steve) arms are detected automatically and can be switched. The built-in skin editor has pencil, eraser, region-limited fill, colour picker, undo and redo, region outlines and labels, "copy right limbs to left", clear outer layer, and a live rotating 3D preview. You can start from your simple look (an original generated skin) or a blank canvas, and download the result as a PNG. Custom skins are used for your hand, third person and in multiplayer: other players see them. Skins are checked on the server (PNG only, up to 12 KB).
- **Server plugins (v10), EssentialsX style:** `/sethome [name]`, `/home [name]`, `/delhome <name>`, `/homes` (2 homes each by default), `/tpa <player>`, `/tpahere <player>`, `/tpaccept`, `/tpdeny`, and `/back` (also returns you to where you died). Owners can change the home limit or turn teleport requests off in World settings or with `/gamerule maxHomes <n>` and `/gamerule allowTpa false`.
- **Anti screen-peeking rules (v10):** owners can hide the minimap and coordinates for everyone except admins (World settings, or `/gamerule showMinimap false` and `/gamerule showCoordinates false`). Coordinates also disappear from the F3 screen.
- **Server admin console (v10):** Multiplayer > Server admin console. Enter your `ADMIN_KEY` to see every world that has been played on this version, who is online and where they are. You can spectate a world or watch a specific player invisibly (others are not told), message a world, kick players, change the player cap or voice, hide the minimap or coordinates, and delete worlds. Use a long random `ADMIN_KEY`; wrong keys are rate limited.
- **Chat:** timestamps, join/leave/death/system messages, rate limiting, duplicate suppression, server-side mute by the owner, and per-player "hide chat" for everyone. Commands start with `/`; type `/help` in game.

### How authority works

The Durable Object runs the **same simulation code** (`src/core/sim/WorldSim.ts`) that single-player runs in the browser, so the rules are identical.

- **Blocks:** reach, break time for the held tool and tier, placement support and collision, and building permissions are validated on the server. The first valid edit wins and conflicting edits are corrected for everyone. Clients predict their own edits instantly and are corrected if the server disagrees.
- **Inventory:** every click, split, quick-move, craft, recipe-book fill, furnace and chest action is sent as an operation and replayed on the server. Clients predict locally and compare an inventory hash on acknowledgement. A mismatch triggers a full resync.
- **Creatures, items and projectiles** are simulated only on the server and streamed at 10 Hz with delta compression, then interpolated on clients.
- **Movement** is client-predicted, sent at about 12 Hz when it changes, and speed-checked by the server. Fall damage is computed by the server from positions. Drowning, lava, fire, cactus and void damage come from reported surroundings, capped by server rules.
- **Identity:** each device has a random player ID and secret. The server stores only a SHA-256 of the secret, so nobody can join as someone else and take their saved inventory. The room owner is identified the same way.
- **Abuse limits:** per-connection message token bucket, 64 KB message cap, field validation on every message, strike counter for malformed input, handshake and idle timeouts, and heartbeats.

## Vanilla Minecraft textures

The vanilla resource pack belongs to Mojang and Microsoft. Its own NOTICE asks that it not be re-uploaded, and the Minecraft EULA does not allow redistributing it. Strata therefore **cannot ship vanilla assets** on a public website, but it can use **your own copy** on your device:

1. On the title screen, tap **Use your Minecraft textures** (or go to **Resource Packs → Import pack**).
2. Choose the Java Edition resource pack zip (the one containing `pack.mcmeta`). It is imported and activated straight away.

The pack is stored only in that browser's IndexedDB and is never uploaded. Once imported, these use the pack:

| Area | What changes |
| --- | --- |
| Blocks | Resolved through the pack's own `blockstates` and model parent chains, including per-face textures, grass side overlays, furnace fronts and cross plants |
| Animation | Water, lava and any `.mcmeta`-animated texture |
| Biome colours | `colormap/grass.png` and `colormap/foliage.png` |
| Items | Through `models/item/*.json` (`layer0`); leather armour is tinted |
| Creatures | Vanilla-proportioned models wear the pack's skins: sheep and wool (Woolhorn), pig (Mudsnout), chicken (Fernhen), zombie (Hollowed), skeleton (Rattlebone), spider and glowing eyes (Duskweaver) |
| Players | The nine default skins (Steve, Alex and others), picked by each player's skin setting; your first-person arm too |
| Sky | Sun, moon and clouds |
| HUD | Hearts, hunger, armour, air bubbles, hotbar, hotbar selection, crosshair and inventory slots |
| Block breaking | `destroy_stage_0-9` |
| Chests | Faces cut from `entity/chest/normal.png` |
| Sounds | Used if the pack includes OGG/WAV files (the vanilla client pack has none, so Strata's synthesised sounds stay) |

In multiplayer, the owner can set a **shared pack** (by fingerprint). Players who have that pack installed see it, and everyone else sees default textures with a note in chat. The owner can also disallow personal packs so everyone sees the same thing. Packs never travel through the server.

### Resource pack compatibility (honest summary)

| Supported | Not supported |
| --- | --- |
| Java packs: `pack.mcmeta`, blockstates (variants and multipart, first match), model parent inheritance, `#texture` references, object-form texture refs (26.x), item models, `.mcmeta` animation (frametime, frame order), colormaps, HD textures (atlas capped at 64 px on desktop and 32 px on touch devices) | Custom non-cube block geometry (Strata draws its own shapes using your textures), CIT/OptiFine features, shaders, fonts, languages, post effects |
| Bedrock packs: `manifest.json`, `terrain_texture.json`, `item_texture.json`, `flipbook_textures.json`, `sound_definitions.json`, PNG and TGA images, `.mcpack` | Bedrock geometry, animation controllers, render controllers, materials, FSB sound banks; Bedrock mob skins only where the layout matches Java |
| Validation report: mapped and missing textures, warnings, fingerprint, preview grid | Executing anything: scripts and HTML inside packs are ignored |

## Controls

### Touch (iPad, iPhone, Android)

- **Left side:** floating joystick. Push to the edge to sprint, or toggle **Sprint**.
- **Right side:** drag to look (multitouch, alongside the joystick). Tap the world to place or use, hold to break where your finger is (can be turned off).
- **Buttons:** Break (hold), Place, Interact, Jump (double-tap to fly in Architect), Crouch (toggle; hold while flying to descend), Fly, plus Pause, Chat, Players and camera view at the top.
- **Hotbar:** tap to select, long-press to drop one. The grid button opens the inventory.
- **Inventory:** tap to pick up or put down, long-press to split or place one, double-tap to quick-move, drag between slots, tap outside to drop.
- **Settings → Controls:** touch sensitivity, joystick size, button size, left-handed layout, auto-jump, and **Edit button layout** (drag buttons anywhere).

### Keyboard and mouse

WASD move · Space jump (double-tap to fly in Architect) · Shift crouch · Ctrl or double-tap W sprint · left mouse break/attack · right mouse place/use · middle mouse pick block · 1-9 or wheel hotbar · E inventory · Q drop (Ctrl+Q stack) · T chat · / command · V push to talk · M mute microphone · B drop a waypoint · N waypoints and map · Shift+N hide waypoints · F5 third person · F1 hide HUD · F3 debug · Esc pause.

## Features

- **World:** endless seeded terrain in 16×16×160 chunks. 15 biomes: plains, two forest types, desert, highlands, snowy peaks, tundra, taiga, swamp, jungle, beach, river, ocean, deep ocean and islands. Caves (tunnels and caverns), ravines, lava lakes, rivers, lakes, waterfalls, ore veins (coal, iron, gold, aetherite) and mossy boulders. Ruined cairns hold loot chests.
- **Rendering:** worker-pool generation and greedy meshing with face culling, flood-fill sky and block light, smooth lighting with ambient occlusion, biome tinting, frustum culling, a texture atlas with in-place animation, real-time sun shadows (High preset), day/night sky with sun, moon and stars, clouds, fog, rain, snow, thunderstorms and lightning, water waves, plant sway, block particles, block outlines and crack overlays.
- **Performance (v9):**
  - Cave culling uses Minecraft's section visibility graph. Each 16×16×16 section records which of its faces connect through open space, and a search from the camera only draws sections you could actually see. It removed about 30% of triangles above ground and 68% in caves in testing, with identical images.
  - Entities in hidden sections are skipped entirely, like the Entity Culling mod.
  - Fog only covers the last tenth of your render distance (Java 1.18+ behaviour). Volumetric fog and cave darkening were removed. Touch devices can set render distance up to 32.
  - The Idle Frame Saver (Dynamic FPS style) drops to 15 fps in the background and 30 fps when paused or idle.
  - Distant Terrain draws simplified block-column terrain past render distance, up to 512 chunks, built in background workers from the world seed, like Distant Horizons. It uses a quadtree of tiles that get coarser with distance, includes forests, snow, sand and water, and uses colours from your active resource pack. It is drawn in its own depth pass, so the real terrain always wins where both exist, and it is hidden chunk by chunk as real chunks finish meshing. Settings: Video > Distant Terrain (OFF, 16 to 512 chunks) and Distant Detail.
  - Cloud shadows are softer, follow the clouds exactly and fade with distance.
- **Gameplay:** walking, sprinting, crouching (no edge falls), swimming, ladders, flying, fall damage, tool tiers and break times, drops, 60+ recipes with a recipe book, workbench, furnace with fuels, chests, doors, buckets and flowing water/lava, farming (hoe, seeds, wheat growth), saplings that grow, leaf decay, health, hunger, saturation, regeneration, starvation, armour, XP, death drops and respawn. Difficulty runs from Peaceful to Hard.
- **Creatures:** Woolhorn, Mudsnout and Fernhen (can be lured with food); Hollowed (burns in daylight), Rattlebone (archer), Duskweaver (pounces, calm in bright light unless provoked); villagers with trades and a daily schedule. `/summon <creature>` works with commands enabled.
- **Java-style systems (v8):**
  - Movement runs at 20 ticks per second with Java constants: walk 4.317 b/s, sprint 5.612, sneak 1.295, jump 1.2522 blocks, sprint-jumping about 7.1, step height 0.6, ice slipperiness, water and lava drag, ladders.
  - Combat follows Java 1.21: attack cooldown with the crosshair indicator, scaled damage, critical hits, sword sweeps, sprint knockback, 10-tick invulnerability and the armour/toughness formula. PvP is on by default.
  - Natural spawning follows Java's NaturalSpawner: per-player caps (70 monsters, 10 animals within 128 blocks), packs of up to 4, monsters only at block light 0 with the Java sky-light dice, animals on grass in light 9 or brighter, none within 24 blocks of a player. Chunks get animals once when first visited (10% chance, like world generation).
  - Despawning: monsters vanish beyond 128 blocks, and beyond 32 blocks have a 1 in 800 chance per tick once idle for 30 seconds. Animals, named or tamed creatures and villagers stay.
  - Random ticks: 3 per 16×16×16 section per tick (`randomTickSpeed`), with Java crop growth (farmland moisture, row penalty), sapling, sugar cane, cactus and grass-spread chances.
  - Simulation distance (default 8 chunks): creatures, items and arrows further away are frozen in place, as in Java.
  - Villagers follow the Java schedule: wander in the morning, work at their building 2000-9000, meet at the well 9000-11000, go home at 12000. They open and close doors.
  - Gamerules: `/gamerule randomTickSpeed|doMobSpawning|simulationDistance|mobCap|doDaylightCycle [value]`. Changes are saved with the world.
- **Saving:** IndexedDB worlds with autosave every 45 s and when the app is backgrounded, manual save, create/rename/duplicate/delete, export/import backups, and versioned save migration.
- **Audio:** synthesised block, step, creature, UI, water, rain and thunder sounds, cave ambience, and generative music. Master, music, effects and ambience volumes plus mute. Muffled underwater.
- **Mobile and PWA:** safe areas, no zoom or pull-to-refresh, fullscreen where supported, adaptive resolution, Low/Medium/High/Custom presets, installable PWA with offline single-player and an update prompt.

## Testing status

What has been run:

- `scripts/v10-smoke.mjs <server> [admin key]`: homes, tpa, back, voice signalling relay, rule broadcasts, spectating, and the admin API.
- `npm test`: 33 tests covering deterministic world generation and biome spread, meshing correctness and speed, crafting and inventory determinism (client/server agreement), server-side mining validation, fluid flow, fall damage, bows, villages, Java movement speeds and jump height, natural spawning in dark rooms vs daylight vs torch light, despawning and crop growth. The vanilla pack import test runs when the pack zip is present locally.
- `scripts/mp-smoke.mjs` against `wrangler dev`: two WebSocket clients exercise room creation, owner vs guest, block break and place sync, server-validated inventory, chat, chunk persistence, impersonation rejection, kick and ban, commands, and rejoin with saved inventory.
- Headless Chrome (SwiftShader software WebGL) against `wrangler dev`: title, world creation, single-player loading and rendering, iPad-emulated touch controls (look, break, place, joystick walking, inventory, recipe book), importing the Java 26.3 vanilla pack (60/62 blocks, 73/74 items, animated water/lava, all six creature skins, player skins and HUD sprites confirmed in screenshots), and **two independent browser sessions** in one multiplayer room (UI create, code join with preview, both players visible to each other, chat both ways).
- `wrangler deploy --dry-run`: bundle and bindings validated.

Not yet tested:

- **Real devices.** No physical iPad, iPhone or Android device, and no Safari engine, has been tested. The touch layer was exercised with emulated pointer events in Chrome. Please try it on your iPad and report anything odd (especially pointer behaviour, audio unlock, fullscreen and performance).
- **A live Cloudflare deployment.** Only `wrangler dev` (the same workerd runtime) and a dry run were used.
- **Frame rate on real GPUs.** The software renderer used for testing manages about 11 FPS, which says nothing about real hardware. Adaptive resolution and the presets are there to hold 30-60 FPS, but this is unmeasured.
- **More than two simultaneous players**, long sessions, and Durable Object CPU usage under load.

## Known limitations

- Fluids use simplified Minecraft-style rules: 7-block water spread, 3-block lava spread, infinite water sources.
- Torches can be placed on floors and walls. Logs are always vertical. There are no slabs, stairs or redstone.
- In multiplayer, creatures are removed when their chunk unloads (no players nearby) and are not saved; single-player worlds save them. Light levels on the server are estimated from block data (exact for enclosed rooms and caves, slightly approximate around leaves and water).
- Very high render distances (16+) are heavy on tablets; Distant Terrain is the cheaper way to see far. Distant Terrain shows the generated world, so player builds far away only appear once their chunks load.
